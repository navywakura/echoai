## 4. Arquitectura: un solo modelo, cuatro generaciones

Todo vive en **un único paquete Python, `echoai`**, que se compila en **un solo binario**
(`echoai.cpython-314-x86_64-linux-gnu.so`, 76 MB), más los 6 módulos del núcleo WSP
(`navi10_*`). Cada generación **importa** la anterior; ninguna la copia.

```

├── navi10_wsp.py  navi10_cam.py  navi10_qn.py  navi10_spoke.py  navi10_dag.py  navi10_stdp.py
│        └── paquete WSP de 16 B, CAM de 4096 ranuras, vértice Q_N, codificación: el «cable»
└── echoai/
    ├── nexus0/            ── ECHO-1 y ECHO-2 (58 módulos), y los paquetes de ECHO-3
    │   ├── types encoder qtable gate loop world env attend escalate oracle plan thought
    │   │                   ← NÚCLEO de dos relojes: S→A→Ŝ→S'→δ→aprendizaje (ECHO-1)
    │   ├── room1 obj1 open1 sign signc qwen_signc talk talk1 pattern0 xfer1 corridor body self1 …
    │   │                   ← cadena situada de ECHO-1
```

### Cómo encajan las cuatro generaciones en tiempo de ejecución

```
            córtex (opcional, BYOK: Qwen / Phi / cualquier API) ── solo HIPÓTESIS
                                   │  pasa por el cortafuegos (SITUATE-2)
┌──────────────────────────────────▼───────────────────────────────────────┐
│ ECHO-4  un agente, una memoria: cuerpo (MAINTAIN) + tribu (ROLES)         │
│         + continuidad + «sé qué soy» (SITUATE)  → integrate.py            │
├──────────────────────────────────────────────────────────────────────────┤
│ ECHO-3  adaptadores de sensores, PX4 y dron (SITL); misma CAM/T/Q/gate    │
├──────────────────────────────────────────────────────────────────────────┤
│ ECHO-2  cuerpo viable, turnos, sueño, generalización (sobre el loop)      │
├──────────────────────────────────────────────────────────────────────────┤
│ ECHO-1  núcleo de dos relojes: WSP 16 B → CAM → T → Q → gate (enteros)    │
└──────────────────────────────────────────────────────────────────────────┘
```

Ejemplos de que es **un solo modelo** y no cuatro copias:
- `echo4/situate.py` resume en una huella `nexus0/loop.py` (ECHO-1) como parte de «qué programa soy».
- El cuerpo de ECHO-4 es una cadena de herencia que termina en ECHO-1:
  `MaintainControl → MaintenanceAgent → SelfAgent → BoundaryAgent → SensationAgent → nexus0.loop.Agent`.
  Cada fase de ECHO-4 añadió una capa sobre el mismo agente, y la memoria es la CAM de `navi10_cam`.
- Una sola regresión cubre las cuatro generaciones: 869 pruebas de ECHO-4, 488 de ECHO-1
  y las de ECHO-2/3 en `tests/`.

## 5. Qué no afirma esta versión

- No afirma conciencia, sentimientos, vida ni inteligencia general.
- No tiene resultados en hardware: ECHO-3 está en SITL y la validación física de ECHO-4 viene después.
- Los visores (GUI-4, METAVERSE-1) no están en el paquete.
- REL-D, la publicación, no se ha hecho.
